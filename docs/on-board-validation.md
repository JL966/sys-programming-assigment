# 下板分层验证步骤

本文件只记录操作方法。执行后把实测值、日志、照片路径和操作者写入 `test-record-template.md`；编译成功不能替代此表。

## 0. 构建与烧录前提

1. 激活学校或课程提供的合法完整 Keil C51 许可证。
2. 运行 `powershell -ExecutionPolicy Bypass -File firmware/build-all.ps1`，必须得到三个 HEX，且日志没有 `FATAL ERROR`。
3. 记录三个 HEX 的 SHA-256 和生成时间。
4. 在 STC-ISP 选择 STC15F2K60S2，逐板烧录匹配角色；重新上电后不要让串口助手占用 COM。

## 1. 单板 G1

每块板分别执行：

- [ ] 上电安全初态：LED 灭，无电机动作，数码管首位显示角色 1/2/3。
- [ ] PC 以 2400 bps 发送 protocol.md 的 HELLO 黄金帧；校验响应角色、协议、固件和档案。
- [ ] 连续 100 次不同 seq 挑战，首次正确响应数必须逐条保留；目标是 100/100，不隐藏超时。
- [ ] 发送错误 CRC、版本、地址、payload 长度和半帧；不得执行动作，随后合法帧仍能接收。
- [ ] 记录 `MainLoops`、`PollingMisses`、RX overflow 和 TX high-water。

## 2. 双板到三板 G2

- [ ] 仅 DUT/REF，1200 bps 进行双向挑战，每方向先 2 次再 10 次。
- [ ] 加入 CTRL，确认普通事务任一时刻只有一个发送者；未经 TX_LEASE 的节点不发测试帧。
- [ ] ARM 后遮挡红外：本 attempt 为 FAIL/TIMEOUT；预检前遮挡导致前提不成立则为 BLOCKED。
- [ ] 移除遮挡，以新 attempt 复测 PASS，旧 FAIL 保留。
- [ ] 断开 485 后，通过 DUT/REF 独立 USB 判断节点仍运行；只能定位到“485 路径”，不能直接判 MAX485 损坏。

## 3. 核心 G3

- [ ] T01 UART1：明确测试的是 CTRL、DUT 还是 REF，不能用 CTRL 代替 DUT。
- [ ] T02 RS485：DUT↔REF 双向内容、trial、CRC 和耗时一致。
- [ ] T03 IR：固定距离和角度，每方向 10 次，记录环境条件。
- [ ] T04 RTC：跨 10 秒和跨分钟；BCD 合法，允许误差按配置冻结。
- [ ] T05 EEPROM：备份 → PC 保存确认 → 写模式 → 读回 → 恢复 → 再读 CRC；任一步失败停止写入。
- [ ] 运行中取消、节点复位和 PC 关闭串口均不留下持续输出或未记录写入。

## 4. P1 条件项目

- [ ] 温度：保存原始 ADC，人工加热后变化方向和最小变化量达到冻结规则；不宣称绝对温度精度。
- [ ] 光照：基线 → 遮光 → 恢复，保存三段原值；未恢复则 INCONCLUSIVE。
- [ ] 超声波：固定平面和尺量距离；无新鲜度证据的恒定值不得自动 PASS。
- [ ] 按键/导航/霍尔/振动：PC 逐项提示，事件只消费一次并带时间戳。
- [ ] LED/数码管/蜂鸣器：保存操作者确认，automation 必须为 MANUAL。

## 5. 发布回归

- [ ] 正常快速整轮连续 10 轮；取消 5 次；冷启动 5 次。
- [ ] 非写入长稳 30 分钟；记录最差而非只记平均性能。
- [ ] 关闭 PC 页面但保持板供电，验证 CTRL 固定子计划和概要；需要 PC 的项目明确 BLOCKED。
- [ ] 换目录或换电脑，断网启动网页，按 README 复现。
